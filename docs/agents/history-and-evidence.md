# 会话与证据检索

查旧决定、复盘、错误或验证来源时，从[复盘索引](../retrospectives/README.md)进入，
再按session ID、UTC时间和原始记录行号定位。[来源清单](../retrospectives/2026-10-18-sources.md)
说明范围与局限；[机器索引](../retrospectives/sessions.json)便于筛选。

## 原始会话

- 优先按 `session_meta.payload.cwd` 选项目，规范化大小写、分隔符、Windows扩展路径前缀。
  需要覆盖worktree时，另核对共同仓库身份，不能只对标题作关键词搜索。
- 同时查 `$CODEX_HOME/sessions` 和 `archived_sessions`，支持`.jsonl`及`.jsonl.zst`。
  压缩日志可流式解压；不要把只找到未压缩文件当成全部历史。
- 先读metadata，再只扫描选中项目的记录。保存固定截止范围、源格式、父子关系和摘要，
  避免当前复盘不断把自己的新记录重新纳入。
- `response_item`、`event_msg`、工具调用及结果各有用途；本机记录的assistant阶段字段为
  `phase: final_answer`。先核对格式再解析，不能因为读错字段推断“没有最终回答”。
- 主会话、子会话及继承的父上下文分别计数，同一测试结果不能重复视为独立验证。
  role=user也可能承载工具/子会话通知；授权须识别实际人类请求。

## 证据等级

1. 当前源文件、版本化规则/契约与可复跑测试。
2. 原始会话的具体操作/结果，以及当时的持久化报告和构建证据。
3. 历史总结用于导航；来源缺失时明确标注，不能把记忆描述当作当前状态。

摘要不能代替原始失败原因。读取大results.json或MCP响应时，先投影stats、失败项、
错误、指定附件和必要字段；避免把18MB报告、全工具目录或重复上下文直接送入模型。
先核对现有检查器和CI接线，防止把已经实现的保护再次当作新需求。

## 保存边界

项目内保存结论、短脱敏证据、来源定位、哈希和限制；完整私人会话日志留在原存储。
不要复制患者信息、身份字段、cookie、token或无关项目内容。
已过期的Vite临时token也可在派生摘要中脱敏，同时保留原本地失败记录。
新发现以补充记录和新证据版本保存，不能改写原始记录使它看起来一直通过。
