# 桌面更新使用院内更新源并由医生决定安装时机

- 状态　产品边界已确认
- 范围　运气通 Windows 桌面版

向各诊室逐台部署新版耗时，医生也需要在断网时继续使用运气通。新版通过与诊室电脑处于同一内网的服务器统一发布。计算、量表和现有离线安装路径继续可用。

后台下载以医生的业务连续性为先。运气通运行期间，只有 Windows 已锁屏且系统 CPU 和可用内存有余量时才静默下载。更新包支持分片和断点续传。解锁或资源吃紧时暂停，待再次满足闲时条件后继续下载。

下次医生主动打开运气通时，在应用内提示下载完成，提供「重启并更新」「下次启动时安装」「稍后」。当前会话存在时，重启前提示会话将结束。医生明确选择「下次启动时安装」后，下一次启动才尝试自动安装所选版本。

安装前短时复核所选版本的放行状态，并复验本地包签名。院内更新源对本次请求的随机挑战、所选版本和安装包哈希签名，客户端用预置公钥校验放行结果。更新源不可达或放行确认无效时进入现有版本。收到所选版本已撤回的可信结果时，取消对应的安装授权。

每次发布面向全部符合条件的诊室电脑提供同一版本。各台电脑异步、无固定顺序地获取分片，错开大流量下载，按医生选择的时机安装。院内更新源初期按简化部署要求使用同一内网的 HTTP 服务。

服务端同一时刻最多传输一个更新分片，并限制传输速率。客户端逐片写入本地，遇到服务忙时随机延后重试。已有分片可在同一包的后续下载中复用。先用 2–4 MiB 的片大小进行工程验证。医生触发的本地安装按各台电脑的时机执行。

日常更新包包含运气通、进程内 Rust 规则引擎及离线工作台资源，复用符合版本要求的本机 WebView2。完整离线包用于首次安装、在 WebView2 不满足要求时覆盖升级及修复。

首批诊室电脑尚未部署运气通。首次分发直接使用带自动更新能力的完整离线包。工程环境保留覆盖升级验证，用于检查应用标识、安装范围和本地偏好的兼容性。

交接安装器之前出错时，继续运行现有版本。覆盖安装失败后停止自动重试，原版仍可运行时继续使用。需要修复时，由信息科使用事先验证过的完整离线包恢复。运维侧保留一份上一可用版本的完整离线包。

CPU 和可用内存阈值、具体片大小和速率上限以工程验证结果为依据。
