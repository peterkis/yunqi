# 运气通桌面自动更新实施与验收计划

首批诊室电脑直接安装支持自动更新的完整离线包。后续版本由院内服务器统一放行，各台电脑在下载闲时领取精简更新包，并按医生选择的时机安装。[架构决策](../architecture/adr/ADR-003-desktop-intranet-updates.md)

## 实施顺序

1. **建立院内更新服务和发布流程。** 从同一桌面源码为 Windows x64 构建完整离线包和日常更新包。发布清单绑定版本、目标平台、包大小和摘要，安装包签名由发布环节生成。院内 HTTP 服务提供发布清单、分片和绑定请求随机挑战、版本、包摘要和完整签名载荷摘要的放行复核。先使用测试地址和测试密钥演练发布、暂停和撤回；诊室交付使用正式院内地址和配置好的信任公钥。
2. **接入桌面下载。** 由 Tauri 原生宿主管理更新。Windows 锁屏后检查系统 CPU 和可用内存，满足下载闲时条件才发起分片请求。分片逐片写入本地，包身份一致时从已完成的片继续。解锁或资源吃紧时暂停传输。服务端全局一片一传并限速，客户端在开始及服务繁忙重试时随机错开时机。
3. **完成提醒、授权和安装。** 医生主动打开运气通时显示应用内提示。安装授权绑定完整发布清单，按「重启并更新」或已选的下次启动时机执行。交接安装器前完成包验签、WebView2 条件检查和短时发布复核，并结束当前工作台会话、关闭随包计算进程。断网或复核失败时进入现有版本。可信撤回或清单替换取消对应的待安装授权。
4. **验证修复和首批交付。** 在工程环境验证从完整离线包全新安装，再通过测试服务更新到下一版。保留旧试装包到新包的覆盖兼容性验证。演练安装中止和信息科使用完整离线包修复，再交付带更新能力的完整离线包、后续版本发布操作说明及验收记录。

## 验收

| 场景 | 通过条件 |
| --- | --- |
| Windows 10 和 Windows 11 首装 | 完整离线包可在断网环境安装，原有计算、量表及桌面窗口操作通过回归。 |
| 多台电脑同时锁屏 | 分片传输并发峰值为一，下载速率在配置上限内，繁忙请求分散重试。 |
| 解锁、断网、资源压力和重启 | 解锁或资源压力触发暂停，断网后业务继续，恢复下载闲时后复用已完成分片。 |
| 医生操作与性能 | 应用内提示不抢焦点，正在填写的会话可继续；记录下载、验签期间的 CPU、内存、磁盘和网络峰值，并复测 350 ms 收起行为。 |
| 安装权限与撤回 | 授权仅用于医生选定的完整发布清单，破损包、过往签名响应、已撤回版本和已替换清单均无法安装；复核超时后进入现有版本。 |
| 覆盖更新与恢复 | 精简包验证 WebView2 前置条件后覆盖更新，桌面偏好保留；覆盖失败停止自动重试，已验证的完整离线包可用于修复。 |

分片大小先在 2–4 MiB 范围试测。CPU、可用内存和传输速率阈值以诊室同等配置上的测试结果为依据。测试记录报告实测结果和未覆盖的环境。

### 放行协议升级

客户端与服务端需一起升级：旧客户端的放行路径不再受理，新客户端也不接受缺少清单摘要的旧放行响应。混用时继续运行当前版本，不执行自动安装；已预约的旧格式授权不会迁移，升级后按最新清单重新确认。已有旧客户端时，使用已验证的完整离线包过渡。清单替换后，如包摘要、长度和分片摘要一致，可复用本地分片，但须重新确认 WebView2 门槛与安装授权。
