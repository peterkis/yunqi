# 运气通 0.2.1 工程审查与 Windows 实测

工作树为 D:\Projects\YunQi-rust，基于 rust/native-desktop 的未提交改造。审查开始时记录了 1,088 个版本控制内或未忽略的项目文件，包括 505 个 docs 文件。检查覆盖 Rust 核心、独立 HTTP、Tauri 桌面与更新、React 接入、冻结契约、参考实现、验证脚本、CI 和当前维护说明。对历史材料做了目录、引用和校验记录检查。截图、字体、压缩依赖、既往报告的存在性检查，与逐项重做其历史验收属于不同证据。

## Windows 普通启动

旧版为 0.1.10 的原始 Node 安装包，新版为本次重建的 0.2.1 安装包。使用包内 EXE 及相应运行文件直接启动。同机比较，各状态三对交替启动，每次使用新的 WebView2 配置目录，采样点为进程启动后 8 秒及 20 秒。内存为自有进程树 private working set，单位 MiB。每个单元格是同一版本三次启动的中位数。

| 实际窗口尺寸与状态 | 时间 | 0.1.10 | 0.2.1 | 节省 |
| --- | ---: | ---: | ---: | ---: |
| 400×994，鼠标保持窗口展开 | 8 秒 | 254.87 | 182.01 | 72.86 |
| 400×994，鼠标保持窗口展开 | 20 秒 | 201.38 | 164.58 | 36.80 |
| 400×6，贴顶自动隐藏 | 8 秒 | 237.88 | 171.09 | 66.79 |
| 400×6，贴顶自动隐藏 | 20 秒 | 189.20 | 158.25 | 30.95 |

上一轮 0.2.0 用 Release 安装包，Cargo release fingerprint 启用 custom-protocol，未启用 devtools。旧测试脚本显式启用 WebView2 的环回远程调试端口并通过 Playwright 连接。源码及脚本未发现打开可视开发者工具面板的操作。以前报告的 277.63 / 200.31 MiB 是该自动化负载的数据。原始脚本未记录当时的实际视口。此次普通启动未接入 CDP，24 个最终进程快照都核对了命令行。各轮的配置目录是新的。系统磁盘缓存照常工作。本轮没有执行数小时驻留或真实门诊工作负载。

每个版本可见业务窗口均为 1 个，只有一个 WRY WebView 和一个渲染宿主。两个 16×16 HWND 分别服务单实例通信和 Tao 事件分发。两个版本都有 6 个 WebView2 进程。0.2.1 展开 20 秒后各角色私有工作集的独立中位数分别为 renderer 67.49、GPU 56.43、browser 23.91、网络 6.69、存储 2.77、崩溃报告 1.57 MiB。Rust 主进程为 5.74 MiB，私有提交量为 7.57 MiB，总工作集为 49.07 MiB。进程分项单独取中位数，直接相加可能与总量中位数有差别。旧版共 9 个进程，新版共 7 个。差额为 node.exe 与其 conhost.exe。最小化后再次启动复用了原 HWND，恢复前台，第二进程退出。正常关闭时，等待 7 个自己的进程句柄，全部退出。展开测试结束后光标已恢复，窗口偏好文件的前后 SHA-256 相同。[Microsoft 的 WebView2 进程模型说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-model)

## Rust 分配与缓存

| 对象 | 生命周期与上限 | 结果 |
| --- | --- | --- |
| 节气 | 最多 1,836 个 OnceLock 槽。首次读取对应年份和节气时计算 | x64 静态槽为 29,376 B，可以从二进制静态空间解释。遍历全部槽后，活跃堆无进一步增长。 |
| 农历生日 | 1900–2100 年共 201 个惰性年份槽 | 每年由 12 个分散的 Vec 改为一段连续的月份记录，月份名称复用。年份索引静态空间由 59,496 B 降至 4,824 B。 |

| 出生对照与接口返回 | 查询期间临时构建输出 | 复用首个候选，移动已生成的响应树。桌面 IPC 保留 64 KiB 请求限额，计数时避免再生成整段字节缓冲。 |

Linux x86_64 Release 单线程核心探针跟踪分配器请求的活跃字节，各响应在采样前释放。依次调用当前教学、问卷、201 个农历年份后，修复前为 529,589 B，修复后为 163,907 B。第二次走遍 201 年新增 0 B。修复后首次农历查询增加 98,844 B，包含 tyme4rs 的按需初始化。再访问余下 200 年合计增加 42,640 B。双候选出生交界日一次热请求的额外分配峰值由 558,451 B 降至 235,711 B。该测量覆盖应用与库的活跃堆，Windows 工作集另行实测。

同一台 Windows 的独立 x64 MSVC Release 探针也分别启动修复前后两个冷进程。首次教学保留 14,180 B，首次问卷后累计 21,875 B。遍历 201 个农历年份后，释放响应的活跃堆从 529,041 B 降至 163,359 B，第二遍和随后的 1,836 个节气均无净增长。热身后再做 100 次出生对照，最终分别为 551,614 B 和 185,932 B（538.69 → 181.57 KiB），减少 66.29%，这 100 次都未造成持续增长。一次热请求的峰值附加堆也为 558,451 → 235,711 B。该指标不计分配器自身、栈或映射文件。原始数据及探针构建记录在 .artifacts/rust-review-20261127/windows-heap，复现入口为同级的 run-windows-heap.py。

另在 Linux Release 单 CPU 上交错执行七轮，每路每版预热后测量 840 个请求，取每轮中位数再取中位数。核心 dispatch 返回 Value 的当前教学耗时从 176.26 降至 132.04 微秒，交界日出生对照从 1,054.26 降至 589.71 微秒，农历双候选预览从 656.21 降至 569.84 微秒。真实 IPC、页面渲染另有开销。

字体文件共有 17.83 MiB，现行设计要求保留完整中文字库。

## 已修复的其他问题

- 整数参数的 JavaScript 与 Rust 字符串转换出现边界差异。已对齐 BOM 和特定空白字符、带符号进制前缀和大于 u64 的有限进制数的校验结果。原始服务行为及 Rust 回归测试均已核对。
- React 桌面适配层曾在 IPC 两端做多余的 JSON 编解码。现在直接传递结构化请求并消费结构化结果，保留非 2xx 的类型化错误。核心和 Tauri 成功响应均移动计算结果。已清理桌面不再使用的 Tokio process 功能。
- 独立 HTTP 的 /docs/ 使用正确的相对资源链接。静态资源按类别设置 Cache-Control，并处理带权重的 gzip / identity 选择。未压缩形式的 HEAD 请求直接读取嵌入 gzip 的原始长度，省去解压 1,526,593 字节再丢弃的工作。恢复脚本覆盖全部 15 项文档资源。固定资产原始字节，防止 Windows 检出换行转换改变响应。
- 核心差分及 HTTP 对照共同固定到原始 Git 提交 7d6ce9b532407322faffb9f51e31455c394dd69d。验证驱动读取 Cargo 报告的真实 EXE 路径，支持自定义目标目录及目标平台。启动服务和原生单测无需先读取对照摘要。补齐仓库门禁对三个 Rust 检查步骤的约束。构建脚本校验缓存的 Tauri CLI 版本，Windows 自动化基准可使用相对路径，结果注明 CDP 模式。
- 修正了开发手册的默认服务、Windows 与网页胶囊尺寸差异、版本示例、历史计划的一条错误规则链接。原 TypeScript 服务仍向冻结契约的生成、历史差分与测试提供参考。生产包已核验无 Node、worker 或 runtime/service。历史安装包、校验记录和在用的测试基线保留。

## 需要项目方复核

| 问题 | 已有证据及需要决定的事项 |
| --- | --- |
| 固定北京时间领域模型 | ADR-001 要求带本地日期时间字段的 CalendarTime 进入领域。Rust 的 native/src/domain/mod.rs 仍接受 i64，比较时按固定 UTC+08 重建字段。边界与时区测试通过。需决定按 ADR 实现专用类型，或在评审后记录 Rust 接口的变体。 |
| 非有限数值字符串 | 原 Fastify 对个别超契约输入如农历月字符串 Infinity 可返回 200 和空候选，Rust 返回 400。这是标准差分之外发现的差异。需明确支持的异常输入语义，并决定是否在两端统一。 |
| 桌面来源链接 | 经典与量表出处使用 target=_blank，锁定 Wry 的默认弹窗处理会拦截新窗口。需确定离线部署允许交给系统浏览器的来源范围，或采用复制来源地址。 |
| 院内更新通道 | 更新源配置解析接受 HTTPS，实际 release reqwest 未启用 TLS。目前说明及附带发布服务使用院内 HTTP。如实际部署要求 HTTPS，应落实 TLS 后端、证书信任与真机验收。 |
| 独立 Swagger 的条件请求 | 原 Fastify 静态资源支持依赖文件时间的弱 ETag、Last-Modified 和范围请求。Rust 的资产嵌入 EXE。需决定是否要求验证器、304 和 Range 的行为兼容。 |
| 正式冻结与部署 | 规则文件标注“待正式冻结”。需项目方核实正式专家签核记录。当前 0.2.1 为本地工程补丁，未向 GitHub 或更新服务发布，也未覆盖本机安装。 |

## 验证和证据

业务差分 13,985 个响应零差异，原版与 Rust 各 13,985 次 OpenAPI 校验通过，67 个冻结摘要匹配。农历适配另检验 74,772 组查询、1,809 个节气时刻。Windows Release 核心与契约 22 项、独立 HTTP 3 项、桌面 10 项通过。真实 TCP 检查 24 项并另测 HEAD、编码权重、限流与恢复。工作台 87 个测试文件的 776 项通过，全工作区类型和覆盖率通过。工作台语句、分支、函数、行覆盖率分别为 94.29%、92.29%、94.81%、96.23%。

工作区聚合 pnpm test、类型检查、覆盖率和治理检查通过。重新指定 Cargo 目标目录后，Windows 标准差分另跑 1,445 个响应，全部一致。早期一次质量门禁正确报告旧用例没有列入 Rust CI 步骤，修正后重新通过。Linux 全量执行使用锁定的 pnpm 10.32.1，并关闭 Redocly 遥测及更新提示。

包内 WebView 自动化验收覆盖 10 个业务操作、错误请求、固定北京时间、时间线、指定时点数字键盘、出生对照、26 项合成作答、计分、销毁、400×994 展开和 424×78 胶囊。首次自动化等待展开首页时超时，实际窗口为 400×6。排查确认应用资源与业务调用正常，验收器增加对本次自有窗口的展开处理后，同一包内 EXE 全流程通过。失败与成功日志均已留存，成功记录为 smoke-native-hover.log。
