## 本版差异与迁移

1. 按确认单 R-21，`GUEST_GENERATES_HOST` 的解释标签由“客生主”改为“客生主，相得”。“主生客，相得”保留。两个方向仍分别编码，不合并。
2. 按确认单 R-08，对外查询支持范围为 1900–2100 年，具体输入边界由对应 API Contract 明确。计算年初及年末边界所需的相邻年节气仅是内部历法数据，不扩大对外查询范围。
3. 按确认单 R-12，页面主结果采用“某运太过/不及”，五音在括号或术语说明中补充，例如“水运太过（太羽）”。领域 `SuiYun` 继续提供 `element`、`state`、`tone`，不增加 DTO 字段。
4. `@yunqi/domain` 升至 `1.2.0`。所有年度及指定时点结果携带新规则版本；公共结构、枚举、六气名称、岁运映射、主客气顺序、关系方向与时间模型保持兼容。
5. 本次对外查询范围变更须分配新 Contract ID 并保留旧冻结记录；规则版本与解释标签同步记录迁移。`ruleVersion` 仍为字符串字段，其具体值不因本次升级成为冻结投影中的枚举或常量。不得重写旧版规则说明、原始 Word、原始规则包或既有验收证据。

本版不启用确认单中的后续问诊流程、临床意见采集、患者页面、主运、客运、天符、岁会、多学派或医疗推断。确认单 C-02/C-03 允许在受限医生页面使用“主胜客，逆”“客胜主，从”，并要求中性解释；当前 `traditionalLabel` 保持“主克客”“客克主”，不因“可显示”新增评价含义。

## 时间语义

1. 五运六气业务时间统一采用固定北京时间 UTC+08:00；权威历法语义是 `YunQiCalendarTime` 的本地公历字段，不使用 IANA `Asia/Shanghai` 历史规则、服务器本地时区或 DST。
2. API 可接收精确格式的无后缀固定北京时间、`+08:00` 或等价 `Z` 输入；Service 必须通过 Business Time Normalizer 单向归一化为 `YunQiCalendarTime` 后调用 Domain。其他 offset 和宽松日期格式无效。
3. 运气年 `Y` 的范围是 `Y` 年大寒实际交节时刻至 `Y+1` 年大寒实际交节时刻。
4. 边界采用左闭右开：交节时刻本身属于新运气年或新六步。
5. 节气时刻必须由 `CalendarProvider` 提供，默认适配 `tyme4ts`；禁止用固定公历日期替代。

### 客气序列

客气按以下三阴三阳序列循环：

```text
厥阴风木 → 少阴君火 → 太阴湿土 → 少阳相火 → 阳明燥金 → 太阳寒水
```

将当年司天置于三之气，其余客气按序列前后循环；由此终之气必须等于在泉。实现仍须用测试直接验证“三之气 = 司天”和“终之气 = 在泉”，不得只依赖推论。

## 客主关系

六气所属五行：

| 六气 | 五行 |
| --- | --- |
| 厥阴风木 | 木 |
| 少阴君火 | 火 |
| 太阴湿土 | 土 |
| 少阳相火 | 火 |
| 阳明燥金 | 金 |
| 太阳寒水 | 水 |

五行相生：`木→火→土→金→水→木`。

五行相克：`木→土→水→火→金→木`。

关系判定按以下优先级，必须且只能返回一个值：

1. 气名完全相同：`SAME_QI`
2. 五行相同但气名不同：`SAME_ELEMENT_DIFFERENT_QI`
3. 主气生客气：`HOST_GENERATES_GUEST`
4. 客气生主气：`GUEST_GENERATES_HOST`
5. 主气克客气：`HOST_CONTROLS_GUEST`
6. 客气克主气：`GUEST_CONTROLS_HOST`

君火与相火必须保留为不同气名；二者只在五行层面同属火。

## 客主关系输出标签

| 判定结果 | traditionalLabel |
| --- | --- |
| SAME_QI | 同气 |
| SAME_ELEMENT_DIFFERENT_QI | 同属火，六气不同 |
| HOST_GENERATES_GUEST | 主生客，相得 |
| GUEST_GENERATES_HOST | 客生主，相得 |
| HOST_CONTROLS_GUEST | 主克客 |
| GUEST_CONTROLS_HOST | 客克主 |

输出继续保留 `qiRelation`、`elementRelation`、`direction`、`traditionalLabel` 四字段。标签只是规则解释文字；不得解释为吉凶、疾病、证型或治疗结论，也不自动细分“相得而和”“相得而病”。
